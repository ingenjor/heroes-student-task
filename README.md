
# Heroes Student Task - Реализация игровых алгоритмов

## 📋 Описание проекта

Данный проект представляет собой реализацию ключевых алгоритмов для пошаговой стратегии "Heroes". Проект включает 4 основных алгоритма, которые отвечают за генерацию армии противника, симуляцию боя, определение доступных целей и поиск кратчайшего пути.

## 🎮 Запуск игры

1. Распакуйте архив с игрой `heroes.rar` (путь без кириллицы)
2. Замените файл `obf.jar` в папке `heroes/jars/` на предоставленный `heroes_student_task.jar`
3. Запустите игру:
   - Двойной клик по `Heroes Battle-1.0.0.jar`
   - Или через терминал: `java -jar "Heroes Battle-1.0.0.jar"`

## 📊 Реализованные алгоритмы

### 1. GeneratePreset - Генерация армии компьютера
**Класс:** `GeneratePresetImpl`
**Метод:** `Army generate(List<Unit> unitList, int maxPoints)`

**Описание:** Формирует оптимальную армию компьютера в рамках ограничений:
- Максимум 11 юнитов каждого типа
- Общая стоимость ≤ 1500 очков
- Приоритет: атака/стоимость → здоровье/стоимость

**Алгоритмическая сложность:** O(n·m)
- n = 4 типа юнитов (константа)
- m = 11 максимум юнитов каждого типа (константа)
- Фактическая сложность: O(4×11) = O(1)

### 2. SimulateBattle - Симуляция боя
**Класс:** `SimulateBattleImpl`
**Метод:** `void simulate(Army playerArmy, Army computerArmy) throws InterruptedException`

**Описание:** Проводит пошаговый бой между армиями:
- Сортировка юнитов по убыванию атаки каждый раунд
- Удаление погибших юнитов из очереди ходов
- Логирование каждой атаки
- Завершение при уничтожении одной из армий

**Алгоритмическая сложность:** O(n² log n)
- Сортировка: O(n log n) каждый раунд
- Количество раундов: ≤ n в худшем случае
- Итог: O(n × n log n) = O(n² log n)

### 3. SuitableForAttackUnitsFinder - Поиск доступных целей
**Класс:** `SuitableForAttackUnitsFinderImpl`
**Метод:** `List<Unit> getSuitableUnits(List<List<Unit>> unitsByRow, boolean isLeftArmyTarget)`

**Описание:** Определяет юнитов, которые могут быть атакованы:
- Для атаки на левую армию (компьютер): юнит не закрыт справа
- Для атаки на правую армию (игрока): юнит не закрыт слева
- Возвращает пустой список, если подходящих целей нет

**Алгоритмическая сложность:** O(n·m)
- n = количество юнитов в ряду
- m = 3 ряда (фиксировано)
- Фактическая сложность: O(3n) = O(n)

### 4. UnitTargetPathFinder - Поиск кратчайшего пути
**Класс:** `UnitTargetPathFinderImpl`
**Метод:** `List<Edge> getTargetPath(Unit attackUnit, Unit targetUnit, List<Unit> existingUnitList)`

**Описание:** Находит кратчайший путь между юнитами на игровом поле:
- Алгоритм A* с эвристикой Чебышева
- Диагональное движение разрешено
- Учитывает препятствия (других юнитов)
- Возвращает путь от атакующего до цели

**Алгоритмическая сложность:** O(V log V)
- V = WIDTH × HEIGHT = 27 × 21 = 567 клеток
- Каждая клетка обрабатывается в худшем случае 1 раз
- Приоритетная очередь: O(log V) на операцию
- Итог: O(V log V)
